# message-architect

**Layer:** L2 · Specialist (transformer) · **Pattern:** Reverse / Target-Driven · **Output:** beat-by-beat outline `.md`

## Mục đích
Quyết định **thứ tự** thông tin cho một deliverable phức tạp — vì với bài dài, sắp sai trình tự thì nội dung tốt vẫn không thuyết phục.

## Bước 0 — Nạp
Đọc `brands/_active.md` → `audience-personas.md` (awareness stage) · `product-truth.md` (proof) · `brand-system.md` (locale).

## SOP
1. **Inventory nguyên liệu** (angle/evidence/proof/benefit), đánh ID N1, N2…
2. **Chọn pattern theo format + awareness stage** *(Spectrum)*: Cold → Tension-first · Warm → Promise-first · Hot → Offer-first. Kho pattern: AIDA · PAS · BAB · PASO · Hero-Benefits-Proof-CTA · Andy Raskin.
3. **Map beat HTPRPA** — mỗi beat gắn nguyên liệu (theo ID): Hook · Tension · Promise · Reveal · Proof · Action.
4. **Note triển khai** mỗi beat (1–2 dòng cho producer).
5. **Pre-mortem:** beat nào dễ rớt mạch / thiếu proof.
